# 角色菜单授权

Yak Security 将页面入口和操作能力拆成两层授权：

- `yak_security_menu`：保存稳定菜单编码、父子关系、路由、排序及菜单对应的读取权限。
- `yak_security_role_menu`：保存角色可见菜单。
- `yak_security_permission` / `yak_security_role_permission`：继续保存新增、编辑、删除等操作权限。

前端页面组件仍由代码注册，数据库不保存可执行组件名称。菜单编码应与宿主应用的前端导航元数据保持一致，避免数据库内容被用于任意组件加载。

## 角色配置

角色详情的原有权限树会新增“菜单权限”分组。前端仍提交同一个 `permissionIdList`：

- 正数是普通权限 ID；
- `-1` 是菜单虚拟分组，不持久化；
- 小于 `-1` 的值由框架解码为菜单 ID，并写入 `yak_security_role_menu`。

菜单绑定的读取权限由角色菜单关系自动推导，不应再单独配置。这样取消菜单时，页面入口、直接 URL 访问和后端读取接口会一起失效。

## 数据归属

框架迁移已合并到 `V1__init_yak_security.sql`。该基线会创建通用的菜单表和角色菜单关系表，并初始化 Yak Security 自有的 `system` 系统管理权限与菜单目录；不会包含宿主应用的业务菜单、路由或权限编码。

宿主应用应在自己的资源目录中提供 Yak Security 迁移脚本：

```text
src/main/resources/yak-security/db/migration/
```

该脚本负责：

1. 初始化本应用的业务权限目录；
2. 初始化本应用的业务菜单和路由元数据；
3. 根据历史读取权限回填角色菜单；
4. 按应用需要处理超级管理员或旧版本兼容数据。

Yak Security 的独立 Flyway 会扫描同一 classpath 位置，因此应用迁移会和框架迁移在同一个安全数据源中按版本顺序执行。宿主迁移版本必须高于框架基线并避免与其他依赖中的版本号冲突。
